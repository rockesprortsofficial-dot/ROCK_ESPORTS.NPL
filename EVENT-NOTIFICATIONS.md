# Tournament and Registration publication notifications

The existing public Web Push service now announces real Tournament and Registration publications in Nepali and English. It sends only to devices that enabled notifications and opted into public announcements. Notification clicks use the existing service worker routing to Tournament or Registration. Installation, calls, CONNECT, WOW and TDM behavior are preserved.

In the owner Tournament editor choose TEST (default, silent) or REAL PUBLISH. A real Tournament must also have status Published, then use SAVE ALL CHANGES. In Registration choose the publication mode, enable REGISTRATION OPEN, complete the settings and use its existing Save button. A scheduled registration announcement includes its opening time; an expired/closed registration cannot broadcast.

New defaults and historical data are silent. Automatic requests occur only after a successful save of the corresponding source. They are authorized by the existing confirmed Owner login in the Edge Function. The service-only rock_event_notice RPC reads saved real/test/status fields and constructs the bilingual content from saved names/dates/prizes; caller text cannot forge a public event message. No individual player's registration or contact details is announced.

Tournament publication UUIDs are retained in their existing JSON objects. Registration UUIDs derive from event title, date and active formats, so retries and reopening the same event retain the identity; changing those event identity fields constitutes a new announcement. Existing rock_app_push_deliveries claims prevent duplicate endpoint sends while unfinished batches resume. rock_event_announcements marks completed broadcasts so normal later saves do not notify newly subscribed devices about an old event. A publication's message is frozen for safe retries. Failed/expired providers retain the existing service's delivery handling; provider acceptance is not proof that a device displayed a notification.

No index.html or service-worker.js change is needed. rock-pwa.js lazy-loads the small extension. The extension decorates only the two existing Supabase save builders; existing form validation, saves and public repaints remain in place. Notification failures report separately, retain the saved source and offer a retry for incomplete publication; publishing is never silently reported as delivered. Source saves happen before the request, so closing the browser immediately may require using Retry or saving again to finish an incomplete broadcast.

Files for this change: rock-pwa.js, rock-event-notifications.js, supabase/rock-event-notifications.sql, supabase/functions/rock-app-notifications/index.ts, tests/event-notifications.cjs and this document.

Validation: isolated PostgreSQL tests for real/test, draft/closed exclusions, bilingual content, frozen retry messages and service-only permissions; Edge tests for owner authorization, fan-out, caller-text rejection and completed-publication deduplication; full index.html owner form tests for both saves and failed/test exclusions; existing CONNECT push tests. Production SQL verification runs in a rolled-back transaction, and public API checks exercise config and unauthorized rejection without sending real notifications.
