# Classic four-player registration

Classic uses a separate four-player form matching the approved navy/cyan mockup. Owner Registration settings still control whether TDM, CLASSIC or both are open and their opening/closing times. A Classic-only event opens the Classic form automatically; when both types are enabled, their buttons switch between independently retained drafts. Existing TDM fields, country/consent and the original TDM submit handler remain in place. Existing registration records are not rewritten.

Classic fields: team name, separate team logo, team email and phone; exactly four player cards, each with a real photo, full real name, PUBG name and numeric UID. Duplicate UIDs are rejected. The existing agreement to tournament rules remains. No fifth player, citizenship or unrequested contact fields were added. The live form uses the actual published event title instead of mockup text.

All registration photo/logo inputs now reuse the existing local image converter. Supported native images plus its HEIC/HEIF/TIFF support are accepted. Images are decoded/resized serially on the user's device and normalized to JPEG (portraits) or WebP/PNG (logos, retaining transparency). There is no raw 5 MB selection rejection: the old TDM handler receives already normalized files, while the private bucket retains its existing 5 MB limit and MIME rules. Invalid images or files exceeding browser/decoder resources show a clear error; unlimited file sizes cannot be guaranteed on every device. Originals are not sent to image conversion services. The tested original JPEG was 36,736,648 bytes; the largest uploaded normalized image was 154,292 bytes.

Four player objects are stored together in classic_players JSONB on the existing rock_esports_registrations row, with slot numbers and correctly mapped photo paths. Player 1 also fills the existing scalar player columns so old lists/integrations stay compatible. Team name and team_logo_path remain unchanged for Classic Group Division selection. The new database trigger validates exactly four players, distinct UIDs, separate logo/photo paths, Player 1 compatibility and the active event title. Existing registration-window INSERT RLS and owner-only SELECT/storage policies are unchanged. No storage permission or public-read grant is added. Historical TDM rows get an empty roster default and retain all original fields.

Files upload to an immutable registration UUID folder, one logo plus four portraits. Unchanged retries keep the same UUID/code and skip acknowledged uploads, preventing duplicate records after a recoverable save failure. Changing a draft after failed uploads starts a new attempt; private orphan files from abandoned attempts may need normal owner storage maintenance. The form rechecks the registration window and event before saving. It does not create public announcement pushes, send external team messages or change owner registration settings. The original TDM notification hook remains unchanged.

Owner VIEW FILE for new Classic squads shows the same team/contact and four-player card design with private signed image previews. Approval/rejection refreshes that view. Team HTML downloads and Print/PDF include all four portraits, names and UIDs. DOWNLOAD ALL Excel retains original columns and appends four-player details. Old TDM and historical single-player Classic views/downloads retain their original fallback. Signing out cancels late Classic detail renders and clears the private squad view.

Files: rock-pwa.js (loader), rock-classic-registration.js, rock-classic-registration.css, rock-classic-registration-admin.js, supabase/rock-classic-registration.sql, tests/classic-registration.cjs and this document. No index.html, TDM bracket, WOW, website branding or existing image converter source change is needed.

Validation: isolated PostgreSQL tests for four-player persistence, malformed/duplicate rosters, logo/photo mapping, legacy preservation, closed-window RLS and no public reads. Full-index browser tests submit large Classic and TDM images, exercise duplicate UID validation, interrupted-save retry, owner four-player view, all-player export and desktop/mobile layouts. Existing event/CONNECT and Classic group selection tests pass. Production SQL tests run in a rolled-back transaction. All 19 pre-existing records matched their original data fingerprint after the additive migration; no test registration/photo was saved in production.
